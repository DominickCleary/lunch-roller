# Task: Near-immediate shared game refresh with SSE

- Owner / branch / worktree: Coordinator / `main` / `/home/docleary/lunch-roller`; implementation lanes use separate branches and worktrees as listed below.
- Goal and current behavior: Replace ordinary 30-second browser polling for shared game changes with an SSE wake-up signal. The page currently polls game reads every 30 seconds and refreshes today's result more often near a scheduled draw. SSE is a hint only; the browser refetches authoritative data through existing HTTP APIs. The worker's scheduled draw check remains on its 30-second tick, so draw execution timing is unchanged.

- Dependencies and contracts (link version/commit): Frozen below before implementation; baseline `main` at task start. No new dependency or schema column. PostgreSQL NOTIFY is selected because web and worker already share PostgreSQL and it publishes transactionally across processes.
- Frozen SSE contract: `GET /api/v1/events` is an unauthenticated, read-only `text/event-stream` endpoint. It emits `event: game-state-changed` with an empty JSON object (`data: {}`) as a state invalidation hint. It never includes identity, game state, IDs, odds, balances, participants, places, winner, or draw data. It sends a comment heartbeat every 25 seconds and standard `retry: 3000`. No SSE request changes game state or identity.
- Frozen publisher/listener contract: PostgreSQL channel `lunch_roller_game_state`; payload exactly `changed`. A database trigger sends this signal in the mutating transaction after row changes. PostgreSQL delivers only after commit and coalesces repeated identical channel/payload notifications within a transaction. Both web and worker writes therefore publish without app-specific duplication. The web process owns one PostgreSQL listener and fans each notification to local SSE clients; disconnect and process shutdown remove clients and close the listener. Listener startup/failure must not fail game HTTP operations; browser fallback polling remains active.
- Browser behavior: On an SSE event, EventSource reconnect, and transition back to visible, immediately refresh the same authoritative reads as the current polling path. Keep a slower 120-second ordinary fallback poll, plus existing near-draw/reveal timing. Coalesce refreshes while a request is in flight and run one trailing refresh if needed. Preserve request cancellation/stale-response checks, selected identity scoping, and wheel animation/replay protections. Reconnect itself is a refresh cue; SSE never picks a winner or runs animation.
- Explicit exclusions: No Socket.IO, state-bearing SSE payloads, new broker/infrastructure, browser-side draw selection, identity/admin privilege changes, database schema changes, changes to draw timing/worker tick, push changes, or unrelated UI refresh redesign.
- Acceptance criteria: A committed game-state mutation from web or worker signals connected browsers promptly. Browsers then fetch current APIs and render without changing identity, selecting/rerolling a draw, or restarting a protected replay. Reconnect, tab resume and fallback polling recover missed changes. Connections/listeners clean up on disconnect/shutdown. Transaction failures/retries do not emit pre-commit notifications or event storms. Notifications are generic and state-free. Playwright coverage checks cross-page refresh, identity retention, and recovery behavior where practical.
